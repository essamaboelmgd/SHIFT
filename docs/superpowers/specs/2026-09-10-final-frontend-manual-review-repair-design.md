# SHIFT Final Frontend Manual-Review Repair Design

## Scope

Repair only Process, Project Brief, the mobile Footer, and the recurring chapter-label family on `shift/final-frontend-repair`. Preserve accepted sections, page order, assets, sticky navigation, desktop Footer icon treatment, form contracts, and frontend-only architecture.

## Process

Use the approved Process reference as the visual source of truth. Desktop retains an editorial left column with headline, support copy, progress rail, and three ruled rows. The right column becomes a fixed ALIGN route composition: large ALIGN word, 01 ghost index, IDEA → DIRECTION → IMPACT microcopy, three structural gates, and the orange route/path. It never changes, remounts, or animates in response to stage selection. Left-row selection may update only left-side emphasis and accessibility state. Mobile uses a deliberate reading order and avoids squeezing the desktop split.

## Project Brief

Recover the strongest prior visual direction from Git history, then restore a balanced two-panel composition. Keep the form primary and preserve all fields, validation, payload transformation, adapter resolution, and frontend submission states. Enlarge and redistribute the What Happens Next panel so its heading, three steps, route line, privacy note, and negative space fully occupy the companion panel. Mobile order is headline, form, then steps, with comfortable controls and no oversized gaps.

## Footer Mobile

Change responsive composition only. Preserve desktop layout, configured URLs, social SVG icons, icon dimensions, dynamic year, and content. Mobile becomes a visibly reorganized vertical sequence: brand statement, navigation, contact, social, language status, and baseline, using restrained rules and reduced vertical bloat.

## Chapter Labels

Introduce a minimal shared chapter vocabulary—font family, size, weight, tracking, slash rhythm, orange chapter color, muted context color, and thin structural rule—and apply it through existing section selectors. Preserve each section’s intentional placement and geometry. Do not rewrite copy or reconstruct accepted section headers.

## Verification

Each workstream owns focused tests, build, and diff hygiene. After reviewed integration, run the full checked-in Node tests, production build, `git diff --check`, and delegated targeted rendered QA for changed sections at representative desktop/mobile widths. Accepted sections receive regression inspection only.
